## TL;DR — where we are

We pivoted the project's frontier to **AI sculpting**, per the user's thesis:

> You can't enumerate every building in a dataset. So teach the model to **transform** any
> rough input into a coherent building, and **compose** it from understood architectural
> elements (doors, windows, roofs, towers). Generality comes from transform+composition,
> not from data scale.

Two engines realize this, both **built and validated**:

1. **① SDEdit massing prior** — takes a footprint OR a crude sculpt → a clean, coherent
   building *solid*. (`Stage3aModel.sdedit()`.) **Sculpting output proven CLEAN** (see below).
2. **② Composer → detail** — the part-composer (trained on real BuildingNet part labels)
   decides which elements a building gets (glazing, roof type, dome/towers/steps); `sdf_detail`
   instantiates them (now incl. a **door** primitive). **Validated class-appropriate**
   (religious→dome+towers, residential→hipped, commercial→flat).

The prior is **training now** on a real watertight building corpus (3D BAG, Netherlands).

## Key findings (don't re-learn these the hard way)

1. **Full-generation-from-noise (`images/train_step*_gen_.png`) is SPECKLE.** This is the
   long-known Stage-3a "metric-vs-inference gap" — it persisted before at ~17k iters and
   **more training did not fix it.** *Do not judge the model by these, and do not wait for
   them to clean up.* We never use from-noise generation.
2. **SDEdit (partial-noise) output is CLEAN.** Validated on the 15k checkpoint
   (`scripts/sdedit_bag3d_test.py` → `outputs/sdedit_bag3d/sdedit_bag3d.png`): a crude tower
   edit on a real building → coherent solid building, no speckle. Remaining quality issues are
   **softness/lumpiness** at high strength (under-trained prior) — a *sharpness* problem fixed
   by (a) finishing training and (b) the ② composer/detail layer — NOT a noise problem.
3. **The corpus is the lever for richness, not training length** (see
   `memory/project_sdedit_corpus_ceiling.md`). 3D BAG (Dutch) is enough to validate; for a
   *general* prior, ingest more regions (same `scripts/ingest_3dbag.py`, more bboxes).

## ⚠ GOTCHAS (these cost real time — see also the memories)

- **h5 chunking:** write per-sample SDF corpora with `chunks=(1,64,64,64)`. Auto-chunking
  bundles ~700 buildings/chunk → 19.6 s/batch reads → GPU starves to 0% util. Fixed in
  `ingest_3dbag.py`. ⚠ **The on-disk `data/bag3d_v1/bag3d.h5` is still the SLOW layout** —
  re-chunk it (or re-ingest) if you rebuild; the fast copy `/dev/shm/bag3d_fast.h5` is
  **ephemeral RAM** (lost on job/node end → re-create with the rechunk snippet in
  `memory/project_bag3d_corpus.md`).
- **DataLoader workers HANG** on this h5 corpus (`--nThreads >0` → h5py+fork deadlock, GPU 0%,
  stuck at iter 0). Use **`--nThreads 0`** (same speed — per-iter cost is GPU compute, not
  loading). Also set `HDF5_USE_FILE_LOCKING=FALSE`.
- **DDIM sampler** had a hardcoded `.to("cuda")` in `register_buffer` — **fixed** to be
  device-aware, so inference now runs on CPU or GPU.
- **Bash sandbox** kills network-binding servers (exit 144) → launch the web demo / any
  outbound-network job with the **sandbox disabled** (and `run_in_background` for long jobs).
- **Heavy CPU side-tests starve GPU training** (a CPU SDEdit test pulled 25 cores and slowed
  the run). Run side-tests on GPU, or cap threads (`OMP_NUM_THREADS`).
- The `re_train.py` CIFAR100 procs on the node are **another user (rjaiswa)** — not ours, not a
  bottleneck.

## Training audit — what's MISSING in the prior (2026-06-07)

Source-verified; full write-up `memory/project_training_audit.md`. Distinct from the plateau
finding (more *iters* don't help) — these are training *quality* gaps, several of which explain
the symptoms. Priority:
1. **Class & style conditioning are DEAD** — `bag3d_dataset` sets `style_id=8`+`class_id=0` for
   ALL buildings (3D BAG has no labels) → model conditions only on footprint+height; cannot do
   style/class-conditional generation. Biggest gap vs the goal.
2. **Tall/tower massing nearly absent** — height median 12 m, only 3.3% > 20 m (ingest also
   filtered extent > 90 m). **This is why a sculpted tower stays a wavy column** — coverage, not
   training length.
3. **No classifier-free-guidance training** — `stage3a_model.forward()` has no conditioning
   dropout, so the unconditional branch is untrained, yet inference uses `uc_scale=2.0`. →
   guidance > 1 extrapolates off an untrained model. **Quick win: use `guidance=1.0`** (or
   retrain with `p_uncond≈0.1`).
4. **No held-out validation** (`eval_metrics` is a stub) → overfitting unmeasured.
5. **No EMA** → softer samples.
6. **VQVAE mismatch** — frozen v1 was trained on BuildingNet (broken thin-shell), not 3D BAG
   clean SDFs → plausible softness source.
7. **Corpus narrowness** — Dutch-only + near-duplicate terraced houses.

Symptom→cause: wavy tower = 2+3+5; general softness = 6+5+3; no style/class variation = 1.
**Quickest wins for next session:** `guidance=1.0` at inference; wire `eval_metrics`; add EMA.
Medium: ingest tall/high-rise bboxes (#2); give class/style signal (#1). Larger: finetune VQVAE
on 3D BAG (#6).

**Research → fixes** (papers mapped to each gap, with pipeline fit): see
`memory/project_gap_fixes_research.md`. Highlights: (1) unlabeled conditioning via OpenShape/
MV-CLIP pseudo-labels OR the BAG *gebruiksdoel* function attribute OR cluster-conditioned
diffusion (2403.00570); (2) tall long-tail via CBDM (2305.00562, fine-tunes existing model);
(3) ⭐ **autoguidance** (Karras NeurIPS'24) — guide 30k with the 10k checkpoint, **no retrain**,
fixes the bad-CFG issue immediately; + limited-interval guidance (inference-only); (6) VQVAE
finetune on 3D BAG / 3DShape2VecSet.
