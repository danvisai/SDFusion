## 0. One-paragraph summary

End goal: drop an OSM tile of building footprints, get a 3D town. Three asset
paths are now wired into one pipeline:

1. **Retrieved BuildingNet mesh → Hunyuan3D-2 → simplify → place** (original).
2. **Baked BuildingNet 3DGS → cull/place** (Stage 1, this session).
3. **Procedural SDF recipes per style → marching cubes → optional VQVAE smoothing prior → place** (the "SDF sculpting" pivot, this session).

All three flow through `scripts/osm_hunyuan_pipeline_smoke.py` via the
`--asset_format {mesh, gsplat, sdf_procedural}` switch. SDF retains a footprint
*guardrail* role rather than being the final renderable. A v2 quality upgrade
(densification + kNN init + SSIM + 15 k iters) is in flight as a full-corpus
parallel rebake (8 workers, ~72 % done, ~25 h remaining).

## 1. Project goal (unchanged from earlier docs)

**Input:** OSM tile = a list of building footprints in metric XZ, each with
optional class + height.

**Output:** one 3D scene OBJ or PLY composed of per-building assets placed at
world coordinates.

**Use case:** video-game procedural city generation. Designer drops a map →
gets a 3D layout.

## 2. Current pipeline architecture

```
OSM JSON  →  retrieve_topk (FootprintEmbedNet + kNN over BuildingNet)
              └──▶ rerank (geometry / quality model)
                    └──▶ retrieved_id  ┐
                                       ▼
            ┌────────────────────────────────────────────────────┐
            │  switch on --asset_format:                         │
            ├──── mesh:   conditioning_source → Hunyuan3D-2 →    │
            │             simplify → place_mesh                  │
            ├──── gsplat: load baked PLY → place_gsplat →        │
            │             optional cull_outside_footprint        │
            └──── sdf_procedural: build_styled_sdf(style, poly)  │
                              → sample_grid → marching_cubes     │
                              → optional VQVAE prior pass        │
                              → place_mesh (footprint-faithful)  │
                                                                 │
            ┌────────────────────────────────────────────────────┘
            ▼
      compose (mesh → trimesh.util.concatenate,
               gsplat → scene.gsplat_compose)
            ▼
      scene OBJ (mesh paths) or scene PLY (gsplat path)
```

Placement (shared by all three paths):
- `--placement_mode {fit, aspect_preserve}` — `fit` uses non-uniform
  `[s_xz, s_y, s_xz]` (legacy behavior; can flatten buildings). `aspect_preserve`
  uses single uniform `s = min(s_xz, s_y)` to keep native proportions.
- `--height_policy {osm, area_aware}` — `area_aware` raises OSM heights that
  are unrealistically low for the polygon's area + class. Imported from
  `scripts/osm_recompose_height_policy.py:infer_height`.

Cull (gsplat path only):
- `--gsplat_cull` enables, with `--cull_mask_resolution` (default 256, use 512
  for tighter) and `--cull_dilate_px` (default 2, use 0 for tighter).

### 3.2 Stage 2 — Image-to-3DGS lifting (LGM / DiffSplat) — DEFERRED

Tried to install both; both blocked by env conflicts:
- LGM's `kiui.op.recenter` uses Python 3.10+ union-type syntax; our venv is py3.9.
- MVDreamPipeline needs `xformers` (no compatible py3.9 wheel).
- DiffSplat needs `diffusers==0.32` + `numpy==1.26`; we have 0.36 + 2.0. Risk of breaking VQVAE / SDFusion / Hunyuan if downgraded.

Clean isolation paths exist (separate py3.10 venv for LGM, subprocess bridge) but cost 1–2 h env setup per model. Deferred to whenever Stage 3 commits.

### 3.3 SDF sculpting (Paths A / B / C) — DONE

**Path A — procedural SDF recipes** (2026-05-14):
- `scene/sdf_primitives.py` — torch-native SDFs: box, rounded_box, sphere, cylinder_y, cone_y, polygon_prism (IQ winding), gable_roof, hip_roof. Boolean ops (union, subtract, intersect + smooth variants), transforms (translate, scale, rotate_y), sample_grid + marching cubes via skimage.
- `scene/sdf_recipes.py` — 8 style recipes: `modern, colonial, victorian, industrial, craftsman, mediterranean, contemporary, public_civic`. Each is `recipe(polygon_xz, target_height, seed, **params) → SDF` composing primitives.
- `scripts/generate_sdf_building.py` — standalone CLI: `--style --height --polygon|--polygon_json|--polygon_npy → OBJ`. Optional `--save_sdf .npy` and `--preview_png`.
- Pipeline integration: `--asset_format sdf_procedural --sdf_style <s> --sdf_resolution 96 --sdf_seed_base N`. Recipe is built from the actual OSM polygon (in world XZ), so output mesh is footprint-faithful by construction — no `placed_flat` possible.
- Verified on east4 tile with colonial + victorian styles (`outputs/osm_sdf_east4_*`).
- Known polish items: bay window in victorian recipe can fall outside very irregular polygons; modern/colonial/industrial look similar at low elevation; gable axis is XZ-bbox-aligned (not OBB-aligned).

**Path B — VQVAE neural prior** (2026-05-14):
- `scene/sdf_vqvae_prior.py` — samples procedural SDF on 64³ in Frame N (centered, max-half-extent = 1), clamps to [-0.2, 0.2] (matches VQVAE training trunc), encodes through `logs_building/.../vqvae_steps-latest.pth`, decodes, scales back to world. `procedural_to_mesh_via_vqvae(sdf_fn, polygon, height, vqvae) → (mesh, world_bbox)`.
- Pipeline flag `--sdf_vqvae_prior` (when asset_format=sdf_procedural).
- Verified: produces visibly more organic / rounded shapes while keeping style features (chimney, spire, dome). Slight footprint softening on highly concave polygons (L-shapes); compensate later with a hard footprint-clip post-process if needed.

**Path C — Jupyter sculpting demo** (2026-05-14):
- `demo_sdf_sculpting.ipynb` — ipywidgets sliders for style/height/seed/resolution + VQVAE-prior toggle, live preview via pytorch3d, save-OBJ button. Three footprint sources: rectangle, L-shape, OSM JSON.
- ipywidgets + matplotlib installed in venv.

## 4. Important historical decisions (carried forward from prior docs)

From `docs/HANDOFF.md` (2026-05-08) and `docs/PROJECT_STATUS.md`:

| Decision | Choice | Rationale |
|---|---|---|
| Splits in use | v1 official 1480/186/180 | promoted from `splits_v1_official/` |
| Latent representation | signed SDF | VQVAE round-trips signed SDFs at 0.83–0.99 IoU; UDFs drop to 0.20–0.83 |
| Output extraction | mesh primary (Hunyuan / 3DGS / SDF recipes), MeshUDF as comparison | both integrated; MeshUDF reduces fragmentation but doesn't fix 64³ detail ceiling |
| Mesh deformation (ARAP / biharmonic) | abandoned as primary | libigl fails on BuildingNet non-manifold meshes |
| From-scratch SDFusion-only training | abandoned | never converged; pivoted to retrieval-first then 3DGS / SDF sculpting |
| ControlNet-on-frozen-SD photoreal proposal | abandoned | photometric prior dominates; archived in `legacy/` |
| Watertight mesh repair | NOT done | erases architectural detail |
| Pixel-space DDPM proposal generator | shelved | overfits but pure samples are RGB speckle |
| 3DGS rasterizer | gsplat 1.5.3 (this session) | works on py3.9 + torch 2.8 + cu126 with built-in CUDA |
| Footprint conditioning convention | `(D=z, H=y, W=x)`, footprint placed on `(D, W)` | empirically verified via VQVAE encode→decode IoU axis check |
| Frame N (mesh-frame) | unit-sphere centered, scale = max-extent | matches `preprocess/create_sdf.py` |
| Stage 2 (LGM/DiffSplat) | deferred for env reasons | install hell; separate venv needed |

Style bank (all three paths):
`modern, colonial, victorian, industrial, craftsman, mediterranean, contemporary, public_civic` (8). Used as `--sdf_style` in sculpting path; intended to extend to 3DGS retrieval filter + Stage 3 conditioning channel.

SDF as guardrail: footprint-projection BCE + surface-band SmoothL1 losses live in
`train_sdf_residual.py:43–62` and are reusable. The procedural SDF path makes
footprint adherence structural (the body is the polygon prism by construction); the
3DGS path uses `cull_outside_footprint` at placement. Stage 3 would use the BCE
loss as a training-time guardrail.

## 6. Environment + Gilbreth quirks

- **Always strip XALT preload** for any Python that touches CUDA:
  ```bash
  env -u LD_PRELOAD -u LD_LIBRARY_PATH ./sdfusion/bin/python ...
  ```
- **Home quota is tight** — don't write data/cache to `/home/dsimhadr/`. Use
  `external/_gdown_home`, `external/hf_cache`, etc.
- **Login shells skip `.bashrc`** — there's a `~/.bash_profile` that sources it.
- **`/tmp` is per compute node + wiped on reboot** — anything you want to keep
  goes under `/scratch/gilbreth/dsimhadr/GenerativeTowns/SDFusion/outputs/`.
- **Splits text files lack trailing newlines** — `wc -l` undercounts by 1. Use
  `[ln.strip() for ln in f if ln.strip()]`.

  `env -u LD_PRELOAD -u LD_LIBRARY_PATH code --no-sandbox --disable-gpu`

## 11. Reference papers and external tools (curated, by relevance)

These are the strongest external pointers from research surveys done during
this session. They are *reference architectures* for next-step directions, not
necessarily things to install.

**For Stage 3 (conditional 3DGS generator):**
- **DiffSplat** (Chen et al. 2025, ICLR) — `chenguolin/DiffSplat`. Repurposes SD diffusion for 3DGS generation; natively supports binary-mask conditioning, which maps onto our footprint mask. ~1–2 s/asset inference. Public weights + code. Env conflict with our py3.9: needs diffusers 0.32 + numpy 1.26. Would need isolated venv.
- **GaussianCity / CityDreamer** (Xie et al. CVPR 2025 / 2024) — `hzxie/GaussianCity`, `hzxie/CityDreamer`. Generative 3DGS for unbounded cities; uses a "BEV-Point" representation that *literally extrudes building footprints from a top-down semantic map* — closest published method to what we want. Has a style lookup table built in. Worth heavy mining for Stage 3 design even if we don't use the model directly.
- **GS-LRM / Long-LRM** (Zhang et al. ECCV 2024 / Long-LRM 2024) — feed-forward image-to-3DGS reconstruction. Fast inference. Trained on Objaverse + RealEstate10K, not buildings. Reference for fast feed-forward inference.

**For the conditional SDF recipe generator (option 6 in §9):**
- **GenCAD** (Alam & Ahmed, arxiv 2409.16294). Image → editable parametric CAD command sequence via autoregressive transformer + contrastive learning + latent diffusion prior. Closest reference for "learn parameters of our SDF recipes from data". Engineering CAD focus, not buildings — borrow the method, not the model.

**For sculpting / editing 3D representations:**
- **INST-Sculpt** (Rubab et al. arxiv 2502.02891, Feb 2025). Stroke-based brush sculpting of neural SDFs (ZBrush-style for implicit fields). `Fizza-Rubab/Interactive-Neural-Sculpting`. Relevant if Path C (interactive sculpting demo) needs neural-driven brushes rather than ipywidgets sliders.
- **fogleman/sdf**, **sdfcad**, **wwwtyro/sdf-csg** — the Python SDF-CSG libraries surveyed; we ended up writing our own torch-native primitives in `scene/sdf_primitives.py` because they were either CPU-only or non-differentiable. Reference if expanding the primitive library.

**For image-to-3D scene (full pipeline tools):**
- **Image-Blaster** (Neilson, World Labs) — `neilsonnn/image-blaster`. Claude Code *skill* (not model) that orchestrates World Labs Marble (3DGS environment) + Hunyuan3D-2 (objects) + ElevenLabs (audio). Marble is closed/API-only via Fal. Useful as orchestration pattern reference if option 8 (designer-facing chat tool) is picked. Validates the "environment + object layers" architecture for option 4.
- **EvoScene** (arxiv 2512.08905, 2025), **Bolt3D** (2503.14445, 2025), **FlashWorld** (2510.13678, 2025) — single-image → 3D scene, all newer than Stage 1. Mostly object-scale; mention for completeness when comparing against Stage 2 alternatives.

**For style classification (style bank assignment):**
- 12.3 k-image, 9-class architectural style dataset surveyed (21st Century / Neoclassicism / Eclecticism / Revivalism / Baroque / Modernism / Renaissance+Colonialism / Classical / Early Christian Medieval). Could be used to bootstrap auto-style-labeling for BuildingNet via a CLIP fine-tune. Relevant if option 2 (mixed-style multi-building OSM) wants smarter style assignment than class+area heuristics.
