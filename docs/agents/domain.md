# Domain docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read ADRs under `docs/adr/` that affect the area being explored.
- If either location is absent, proceed silently. Domain-modeling workflows create new files only when vocabulary or decisions are actually resolved.

## Use the glossary's vocabulary

Use the canonical terms defined in `CONTEXT.md` in issue titles, research questions, specifications, hypotheses, and test names. Do not drift to synonyms that the glossary explicitly avoids.

If a needed concept is missing, reconsider whether existing language covers it. If it is a genuine gap, resolve and record it through the domain-modeling workflow.

## Flag ADR conflicts

Surface any conflict with an existing ADR explicitly instead of silently overriding the recorded decision.
