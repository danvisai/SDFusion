## What was wrong with v1 (evidence: outputs/sketch_relief_verify/free_silhouette_fix/)
v1 inpainted art directly into the perspective 3D view, conditioned by that view's
depth/canny ControlNet maps — which contain the composer's window grid. SDXL's strongest
prior for "building photo + architecture prompt" is MORE FACADE: it redrew miniature
window-grid facades inside the padded inpaint box (`star_calib_*.png`), and in the worst
case carpeted the whole building in window bumps (`final_4_result_full_BROKEN_*.png`).
The generic prompt + Canny-outline-only scribble gave the model no idea WHAT the blob
meant, and Depth Anything's raw output put half the motif below the wall plane (smudge,
not carving).

## v2 design (scripts/server/paint_relief.py — the file is heavily doc-commented)
1. **Rectify to wall space** (`rectify_stroke_to_wall`): trace the painter's camera once,
   find the dominant wall plane under the stroke (`wall_frame`: flat_wall_point anchor +
   SDF-gradient normal flipped toward the camera, U/V chosen so the painter sees U-right/
   V-up), resample the stroke onto a frontal orthographic canvas of that patch through the
   camera (occlusion gate: traced depth must agree with the plane point's distance;
   off-plane stroke spill at corners is dropped before the bbox is computed).
2. **Generate bas-relief art on the flat canvas** (`generate_patch_art`): init = stroke
   colors over neutral gray; inpaint region = canvas minus border, AND clipped to the
   actual wall face (|SDF| < 0.08 at plane points — without this, a near-cornice stroke
   hands the model a truncated band it resolves as a storefront sign; found in the live
   UI test). Base depth/canny nets get constant images at [0.2, 0.0]; the xinsir scribble
   net carries the shape (`sketch_thickness`/`sketch_scale` = the UI fidelity slider).
   `relief_prompt()` ALWAYS wraps the subject in "carved stone bas-relief, monochrome
   plaster cast, raking light" (so luminance tracks height); `RELIEF_NEG` carries
   anti-facade AND anti-signage terms.
3. **Read back the model's own silhouette** (`segment_generated_art`): bg-calibrated
   color distance, then pick the connected component that best OVERLAPS the stroke — not
   the biggest (biggest-area was the widespread-relief catastrophe in miniature).
4. **Height** (`height_from_art`): Depth Anything V2 on the mask's bbox crop, then
   (a) plane-DETREND over the motif (DA predicts a scene-level ramp; our reference
   surface is flat by construction) and (b) BASE STEP: remap the motif's 5..95th-pct
   modulation to [base_frac=0.35, 1] × relief_depth so every motif pixel stands proud of
   the wall and the silhouette gets a real step. 0 outside the mask.
5. **Exact fusion** (`refine.py::refine_paint_relief`, since `d6fa606`):
   `final(x) = base(x) + w(x)·((plane(x) − h(u,v)) − base(x))`, with h and a lateral
   falloff (distance transform of the AI silhouette) bilinearly `grid_sample`d in the
   wall's own UV frame; w = lateral falloff × normal-range gate (full effect from
   `reach_in`=0.12 behind the plane — replaces painted-over recesses — to just past the
   relief crest, fading over `band`). **No `fit_displacement`, no KDTree**: v2.0 pushed
   this known-in-closed-form target through the 8-frequency neural fit and it low-passed
   the lion into a lump. Output sampled at `out_res` (default 128, endpoint clamps
   64..160; b64ToVol/raymarch are res-agnostic; 96³-input walls span only ~25–35 voxels,
   so the extra headroom is where the art detail lives).
- `texture_bake._inpaint_view` gained optional `base_control_scales`/`negative` overrides

## Known open items
- **Gates not re-run this session** (`test_branches.py` 12, `test_sculpt_flows.py` 17).
  Risk is low — the only shared-path change is `_inpaint_view`'s backward-compatible new
  kwargs — but run both before building anything on top.
- **No gate test for `/paint_relief` at all yet**; add one (the verify script's flow is a
  ready-made template: /building_sdf → /detail_volume → synthetic RGBA circle → assert
  changed voxels near the stroke and art_png_b64 present).
- Reliefs are **preview-only** by design (same contract as texture bake): the response
  updates the live shader volume only; a second stroke or a Bake re-derives from true
  massing and DROPS earlier reliefs. Fine for demo; revisit if the user wants stacking
  (would need reliefs recorded as edits or composited into base_sdf).
- Corner-straddling strokes are clipped to the dominant wall (graceful; the cross-wall
  part is discarded). Roofline strokes are clipped to the face (no more storefront
  signs) but a stroke mostly ABOVE the wall still yields a small/odd patch.
- Art quality varies seed-to-seed (UI uses a random seed per click — "generate again"
  is the intended recourse; a multi-seed pick-one UI was considered but not built).
- Relief lateral detail is bounded by out_res=128 (~0.16 m voxels in the cube frame);
  the mesh GLB download inherits the same bound.
- Carried over from 2026-07-06, all still open: `propose_detail_ops` buries windows on
  non-convex footprints; weathering only applies on export/rebuild (not live preview /
  textured / neural render); ornament library is 3 pieces (API-key / bot-wall blocked);
  F16 flakes under GPU pressure in full-suite runs; index.html deliberately can't invoke
  the part-layout planner directly (accepted scope gap).
